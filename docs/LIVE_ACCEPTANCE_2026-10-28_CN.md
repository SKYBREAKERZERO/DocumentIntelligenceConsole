## 本次实际修复

- 多轮查询增加“保留页码/content_id”等格式后缀时，仍承接用户明确的上一份 PDF，且不从助手回复猜测文档身份。
- 删除无关查询中硬编码的 550、508→550 提示。
- 对缺少数字编号但物理身份与哈希一致的正文恢复原生向量检索，明确保留未核准标记。
- 为已保存的超长历史章节增加有界字面差异预览，保留前后文字、文本行号及不完整提示。
- 固定的多域 Skills 流程跳过冗余模型规划；不代表起票前条件流程已实现。
- 本地 Ollama 请求绕过环境代理，限制生成长度，遇长度截断不当作完整成功。
- 小上下文先删除旧对话、再按完整证据条款重装；仍不足时明确返回上下文不足，避免原先的异常退出。
- 原有检索 API 新增显式工程的 semantic 诊断操作；有候选时返回 LIMITED，不能把候选数当作答案可靠性。

## 复现方法

先启动既有 PostgreSQL、Qdrant、Ollama、Open WebUI，配置使用本机已有 DIC 用户配置。验收专用 Backend 应在 PowerShell 设置以下只读环境后启动：

```powershell
$env:PGOPTIONS='-c default_transaction_read_only=on -c statement_timeout=15000'
python -u -m app.server
```

发行包中的 `scripts/live_acceptance/` 工具读取已有用户配置，仅连接本地端点、查询生产数据，不输出凭据。运行目录应为项目根目录；这些工具默认将结果写到项目根目录的 `live_acceptance/`，可能包含企业原文，应只在内部保存。不要将该目录上传到公共仓库。

样例顺序：PDF 精确查找 → 跟进“按章节总结一下内容，并保留原文页码和 content_id。” → 110 ServiceList v2.51/v2.52 对比 → 普通本地模型对话。semantic 检索需显式 scope=21MM。复杂 QA 与起票前样例当前会超时，不应反复无变化重试。
