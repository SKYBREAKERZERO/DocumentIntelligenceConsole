## 2. v1.48 实际代码修改

### Q-148-01：工程数值与版本“引用存在但不支持该值”

- 修复前：如果模型写出“超时 600ms。[1]”，而 `[1]` 仅规定 500ms，v1.47 的引用 ID 校验仍会放行。
- 修复：新增 `app/ai/claim_anchor.py`。在 v1.47 生成后缓冲及引用结构校验**通过之后**，按回答句子引用的已接纳 `EvidenceItem` 检查物理量（时间、频率、电压、电流、百分比、分贝、温度）及显式 `vX.Y` 版本字面锚点。
- 值使用十进制精确换算：`500ms` 与 `0.5s` 等价；答复出现 `600ms` 且被引证据没有该值则拒绝；引用另一条包含 500ms 的证据不能代替同句 `[2]` 的证据。
- 不从用户提问、模型回复或任意引用编号伪标题生成许可来源。正文及可信引用标签来自实际送入模型的 Evidence 对象。
- 对拒绝场景，回复原有固定的 `REJECTED_ANSWER`，不泄露未验证自由生成文本。

**仍不具备**：这不是跨语言语义蕴涵校验。若一条要求在 ON/OFF 状态分别使用 500ms/600ms，模型引用同一整条但错误选取 ON 时的 600ms，仅“字面数值出现”仍无法识别错误条件。它也未完整核验否定、例外、公式、单位缺失和带表格结构的数值对应关系。

### Q-148-02：Top-K 样本被冒充“全部技术要求”

- 工程领域使用有限召回，无法从 Top-K 推导全集。新门禁对“所有/全部/完整列出/穷尽”等开放式全量要求采用固定说明拒答，指示收敛具体式样/章节并完成索引覆盖审计。
- 此门禁不改变 PostgreSQL 结构化目录及 QA/BUG 统计的专用路线，也不会对普通非企业聊天启用。
- 本策略优先保证不遗漏关键工程约束；副作用是**有些用户希望获得非穷尽摘要也会被要求缩小范围**。这是已知可用性取舍。

### Q-148-03：遗留证据上下文工具裁切风险

- `EnterpriseRAGService._build_context` 不再将过长技术条款剪成前缀文本。预算不足时跳过整条，防止省略尾部例外、表格脚注和时序约束。
- 主路径 `_build_context_budgeted` 已有该保护，现补齐旧辅助入口。

### Q-148-04：版本发布审计误阻断

- `stage1_release_acceptance.py` 之前固定比较 `v1.47`。更新为解析 GUI 中唯一且显式的 `APP_VERSION`，再与中英文 README 完整第一行比较。版本不匹配继续阻断，不会因为下一次升级无故拒绝。

### Q-148-05：可重复的发布门禁合同

- 新增 `scripts/evaluate_answer_gate.py` 和 `examples/answer_gate_synthetic_v148.jsonl`。
- JSONL 的每个样本必须明确标明 `SYNTHETIC_CONTRACT` 或 `HUMAN_REVIEWED_REAL`；声称真实样本时至少要求提供独立 reviewer 标识和源文件 SHA-256 格式字段，避免把纯合成样本不经声明就计入真实 Golden。
- 此工具仅测**确定性发布规则的预期行为**，不会验证来源哈希指向实际 PDF，也不会验证模型语义忠实度；即便真实样本满足格式也不构成审核者身份认证。
- 合成案例特意保留一条“数值/版本规则不能检测的错误适用条件”正例，用以揭示局限，不能把 100% 规则测试通过误称为工程结论 100% 准确。

## 4. 企业级 AI 回答强制规格（目标门禁，非 v1.48 已实现保证）

1. **文档身份**：明确项目、SPEC_BODY、原始文件 SHA-256、文档版本、适用软件版本和条款章节；封面/审批不能充当技术证据。
2. **规范原文**：保留双端原文、内容 ID、原始位置、页码和版本；缺页码必须标 `PAGE_UNKNOWN`，不得补猜。
3. **主张结构**：对每一事实 Claim 显式映射 requirement_id、条件、状态、数值、单位、时序、例外、表格/脚注及 evidence_id。
4. **冲突/边界**：当参数相同但条件不同、历史生效版本不明确、引用与依赖混淆或没有审核关系时，只能返回证据不足或需要复核。
5. **BUG 五分类**：仅在已批准的软件→式样历史版本映射和审定双端证据存在时给出人工辅助判断；未满足前提默认“证据不足”。
6. **后验审核**：引用有效和字面数值匹配仍不等于语义正确。需要真实 Golden、人工双人标注、误判率、漏判率、逐条件召回率及 P95 延迟验收。
7. **运行与安全**：真实 PG17/Qdrant、权限隔离、冷启动、断线、受限 CPU/内存、Windows GUI/EXE、数据恢复及安全日志均需可复现签收。

## 5. 待解决风险优先级

| 级别 | 阻断项目 | 放行证据 |
|---|---|---|
| P0 | 逐条工程主张的条件/否定/适用版本/例外尚无可验证语义支持 | 508/550 原始 PDF + 人工复核 Golden，独立审核召回/误判指标达标 |
| P0 | 实机真实版本映射与结构关系未经验收 | 真实 PG17/Qdrant 的只读重现、权限、事务、证据漂移审计 |
| P1 | 容易过度拒答，正文覆盖率未知 | 按功能/式样版本的索引覆盖率审计及“拒答正确率”指标 |
| P1 | 流式企业回答需缓存模型全部内容，首 token 延迟和冷启动 | 真实 4B/8B CPU p50/p95、失败率、内存峰值、限时策略 |
| P1 | LangGraph、跨版本依赖与 BUG 五分类未闭环 | 路由/恢复 E2E、审定关系追踪、五分类人工案例集 |
| P2 | 自动化 Ruff、安全扫描、打包 EXE 门禁未现场执行 | CI + Windows 11 构建/签名/安装/回归记录 |

**最终决定**：v1.48 可作为离线研发基线；不得宣称“保证企业级回答正确”或“生产认证已通过”。本次不修改用户 PostgreSQL/Qdrant、不自动批准关系、不添加部署时自动迁移。
