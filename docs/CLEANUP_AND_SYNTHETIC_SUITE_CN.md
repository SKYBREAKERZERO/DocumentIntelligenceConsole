# 假式样清理与典型场景测试

## 本轮结果

按照用户明确指示，已删除找到的 1001、2007 两份虚假 User Profile 式样源文件，以及它们在 21MM 中的登记、正文、关联派生记录和向量。其余工程、真实式样、QA/BUG 记录及网络配置没有修改。新编的 990xxx 样本只用于独立验收库，未导入生产。

“SQL 片段数”和“式样本数”不是同一概念。之前核账的 949679 条 QA/BUG 片段不表示有这么多本式样；核账也不能证明磁盘上的真实式样已全部导入。后续测试不以真实资料完整入库为前提。

## 精确清理范围

- `1001_User_Profile_Main_Function_Spec_Rev1.0.docx`
- `2007_User_Profile_Communication_Interface_Spec_Rev2.1.docx`

两个源文件原位于旧项目的 `release_v590/sample_specs/`。原位置已移除，备份文件的 SHA256 与删除前一致。

在 `rag_21mm` 删除的关联行：2 条 specifications、2 份 documents、2 条 specification_versions、23 条 contents、23 条 embeddings、15 条 chapters、21 条 sections、2 次关系提取记录、16 个工程实体、21 条派生关系、44 条关系证据；Qdrant 删除对应的 23 个明确点 ID。只删除沿这两份假文档外键依赖闭包核验过的记录，没有按数字模糊删除其他数据。

删除前备份完整 SQL 行和向量值，执行前再次比对快照哈希、文档身份与向量身份；SQL 删除在单个事务内完成。随后独立核验：21MM/24MM/COMMON 的目标登记和目标文档计数为 0，各现有生产集合中 spec_code=1001/2007 的点计数为 0。

本机可恢复备份保存在项目 `local_backups/fake_1001_2007_20261028_120636_718a96/`，不进入发行 ZIP。里面包含 backup.json、完整向量、源 DOCX、文件 SHA256 清单和删除收据。工作区的 `cleanup_fake_specs.py --restore <该备份目录>` 可恢复 SQL/向量，不覆盖冲突记录；源文件需按 `source_files/files_manifest.json` 从备份复制回原位置。此次没有执行恢复，也没有把“已备份”称为完整恢复演练通过。

模型规划提示中的固定 `SPEC-1001 User Profile` 示例也已移除，改为从用户问题填写空身份数组，避免示例污染检索。离线单元测试中用于算法断言的虚构编号不等同于运行库资料，不会由测试自动导入生产。

## 实测结果

真实本地 BGE、独立 PostgreSQL 和 `dic_accept_*` Qdrant 集合下，11 个场景全部通过：

1. 现象检索到当前版本的 2.2 节、第 3 页正文。
2. 保存的版本变更集包含 1 新增、1 删除、1 修改。
3. 990101/2.5 → 990201/3.1 的双端明确引用候选。
4. QA 票据引用到对应历史版本正文。
5. BUG 描述中的明确文件/版本/章节引用定位到正文。
6. 缺少被引用的版本时保持未解析，不偷偷换成当前版本。
7. 相似票强匹配分支停止式样兜底。
8. 没有强匹配时继续查询式样。
9. 修复后效果字段不能冒充原始观测并形成强匹配；已确认该字段实际存在于隔离 SQL。
10. 21MM 样本不能作为 24MM 正文返回。
11. 人为破坏隔离向量的正文哈希后，该点被拒绝；测试结束恢复原载荷。

额外使用项目真实 PDF 转换管线读取四份源 PDF：12 个目标条款全文、物理页码和章节 ID 均保留。四份 PDF 共 16 页已渲染检查。业务金标准 JSON 从同一受控定义生成并导入隔离库；原生解析验证单独记录，不能把两者混称为复杂企业 PDF 全面解析认证。

本轮扩大的受影响离线回归为 **421 项通过**，不是全仓库测试。详情见 `docs/acceptance/typical_synthetic_suite.json` 和 `synthetic_native_pdf_parse.json`。

测试发现并修复了 BUG 溯源缺口：旧流程只读取 QA 专用参照字段，现在也从 BUG 的原始描述/现象/实际结果读取明确引用，并记录来源字段、去重；向量载荷和原文均不能扩大用户选定的工程范围。

## 清理后的生产快照与限制

21MM 合格 SQL 点为 89849，实际向量点为 54072；仍缺少 37706 个点，多余 1929 个点。本轮没有执行批量补齐或清理这些其他旧点。旧交付报告的计数是删除假式样前快照，保持历史原文；最新快照见 `docs/acceptance/index_coverage_after_fake_cleanup_21mm.json`。

自动审批曾拦截隔离失败记录清理补丁，担心配置可能指向生产。只读核验了实际端口、库名和数据目录后，改为固定隔离连接并在每次写入前检查，随后测试执行通过；该项没有遗留审批阻塞。

以上均为已知答案的合成行为测试，不表示企业真实语义质量、完整查重召回、复杂版式、并发或符合性裁决已通过。没有已审核的适用软件/式样版本映射和完整证据时，符合性继续返回 UNDETERMINED。除这次明确授权的两份假式样清理之外，没有执行其他生产迁移或测试数据导入。
